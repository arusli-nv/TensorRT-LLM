#10 SKIPPED. slot_tokens is fixed per deployment: it is NVLinkOneSided.max_num_tokens_per_rank of the one workspace
    (nvlink_one_sided.py _bound_layout). source_tokens is runtime_max_tokens_per_rank, a per-forward value, and it is
    baked into the functools.partial ConstraintSpec that sizes input `a` during tuning. ConstraintSpec.infer_shape only
    receives input_shapes. Keying on (source_tokens > 0, slot_tokens) would therefore reuse a stale source_tokens: tuning
    inputs would be sized wrong, with possible out-of-bounds reads while profiling. Passing the geometry at call time
    needs an autotuner API change, so it is not trivial. The current cost is bounded: at most one small TuningConfig per
    distinct source_tokens (<= slot_tokens) per (unique_id, extra slots). The autotuner profile key sets constraint dims
    to -1, so none of these entries triggers a re-tune.
