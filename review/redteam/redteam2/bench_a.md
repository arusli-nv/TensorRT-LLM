# Red team A: how TRT-LLM benchmarks WideEP/DEP serving, and where the FT harness departs from it

Notation: H = /lustre/fs1/portfolios/coreai/projects/coreai_comparch_trtllm/users/arusli/src/TensorRT-LLM/.wideep-ft-runs/claude/mvp/harness ; repo = /tmp/claude-161238/work/repo (wideep-ft-dev, close to main).

## 0. What "standard" is
- **Perf-sanity aggregated GB200 R1 FP4 recipe** (repo tests/scripts/perf-sanity/aggregated/deepseek_r1_fp4_v2_2_nodes_grace_blackwell.yaml:9-44): DEP8, MTP1, CUTEDSL, KV fp8 0.8, `server_env_var TLLM_SPEC_DECODE_FORCE_NUM_ACCEPTED_TOKENS=1`, one client: concurrency 1024 (128/GPU) x 10 iterations, using a **fixed dataset file** (`deepseek_r1-1k1k-20480-ratio-1_for_serve.json`, trtllm_custom).
- **Launch**: Slurm `srun --mpi=pmix` with every rank under `trtllm-llmapi-launch` (jenkins/L0_Test.groovy:2002-2005, 2271; jenkins/scripts/slurm_run.sh:45). Rank 0 runs pytest, which starts a plain `trtllm-serve --config` (test_perf_sanity.py:1835-1855, 2525-2545). Aggregated runs: no numactl (numa_bind is only for disagg, :4161). No log-level env, no pinned tactics: every rank tunes itself at startup.
- **Client** (test_perf_sanity.py:2235-2290): `benchmark_serving --num-prompts concurrency*iterations --max-concurrency C --ignore-eos --percentile-metrics ttft,tpot,itl,e2el`. Without a dataset it adds `--random-ids --tokenize-on-client --random-range-ratio 0`. It adds `--no-test-input` unless warm-up mode is on, it has no extra warm wave, and it runs one client process. The metric is client output_throughput / TPOT, checked against a DB baseline.
- **Engine defaults the recipe actually runs**: `stream_interval` is not in the YAML, so the engine default of 1 applies (llm_args.py stream_interval default=1). The value 10 at test_perf_sanity.py:1716 is only the DB column. `num_postprocess_workers` is 0 and `print_iter_log` is false.
- **WideEP standard** (examples/wide_ep/slurm_scripts/config.yaml, via examples/disaggregated/slurm/benchmark/run_benchmark.sh:152-175): disagg gen DEP32 with `print_iter_log: true`, `stream_interval: 20`, `num_postprocess_workers: 4`, explicit `max_seq_len`, `numa_bind: true`, and `TLLM_LOG_LEVEL=INFO TRTLLM_SERVER/WORKER_DISABLE_GC=1 TRTLLM_ENABLE_PDL=1`. The client uses num_prompts = concurrency x multi_round(8), a fixed dataset and `--no-test-input`. examples/configs/database also uses print_iter_log true, stream_interval 10/20 and npw 4.
- **Blogs**: blog04 uses `numactl -m 0,1` on GB200 (blog04:668; wide_ep/README.md:126). Its EPLB results use **real datasets** (machine translation, GSM8K; blog04:110-173, 520-560), not random ids.

## 2. Minimal-deviation method
**Must differ for FT (FT-on arm only):** (a) the ULFM mpirun with `--with-ft ulfm`, ob1/TCP and the detector. srun/PMIx cannot do ULFM. (b) The FT config (`TLLM_FAULT_TOLERANCE_*`, failure_domain node) plus the authority process on node 0 (serve.sh:225-258). (c) FT's extra/ghost slots (part of FT's cost by design). (d) In kill runs only: the trigger hook and the victim's replay wrapper.

**Must be identical, and standard where possible:** the wheel (one build of record), the YAML body (std-*.yaml already shares it byte for byte), the tactic policy (both self-tuned, or both pinned from tables tuned on their own layouts), env (GC/PDL/forced acceptance/FMHA), numactl, logs on node-local disk, samplers (off), page-cache policy, client binary and flags, loads/waves, arm order (ABBA), and node set.

**Three-arm decomposition per EPLB mode:** `noft` (deployment without FT), `noft-ulfm` (launcher cost), `ft` (mechanism + slots). The headline FT cost = ft vs noft. Plus one anchor `noft` arm launched **truly stock** (srun --mpi=pmix + trtllm-llmapi-launch, perf-sanity style) on main's wheel. Today's WIDEEP_STOCK still goes through PRTE mpirun (serve.sh:371-373), so it is "stock config", not "stock launch".

## 3. Ranked recommendations for the overnight finals
1. **One code identity.** Run cost and kill packs on the same wheel (no overlay on one but not the other). Rebuild rc1+final8 or overlay both. (#19)
2. **Tactics.** For each headline pair, add a self-tuned (AUTO) round, or show that pinned and AUTO agree. Gate every pinned case on TACTIC_CHECK autotune=0, cache_miss=0. (#5)
3. **Ordering and n.** ABBA on the same nodes, >=3 pairs, at the headline load (128/GPU, the recipe's point; 8 and 32 secondary). Prefer fewer EPLB modes at higher n over three modes at n=2. (#21, #12)
4. **Align kill and cost deployments.** Same CUDA graph sizes (#6) and the same A2A path (FORCE_CFT, #11). Otherwise "throughput after recovery" is not comparable to the healthy cost.
5. **Samplers off and logs local** for all final cost arms (#16, #4). Keep `ps`/`nvidia-smi` polling for diagnostic jobs only.
6. **Add the noft-ulfm arm in STD** so the launcher cost is reported apart from the mechanism cost (#1). Add one std-*-main FT-off arm (#18).
7. **Headline client metrics** (output_throughput, mean TPOT, p99 ITL) from benchmark_serving. Rank-0 step medians are attribution only (#20).
8. **Disclose fixed overrides in one table:** max_seq_len 2304, stream_interval 10/npw 4 (cite WideEP/database, not perf-sanity), TLLM_FMHA_LIBS=-cute_dsl_mla with the bug evidence, host_cache_size 16 GiB (justify or drop), backlog 16384, warm wave, page-cache drops, numactl, PRTE `--bind-to none`. Remove TRTLLM_KVCACHE_POOL_USE_FABRIC_MEMORY (no effect in aggregated mode).
9. **Real-text check**: one FT-off/FT-on pair with `--text-prompts`, or the recipe's dataset, for any EPLB-mode claim (#14).
10. If 512/GPU stays, label it beyond-recipe (8 client processes, backlog patch, merged metrics) and keep it out of the headline (#3, #12).

**Reviewer-distrust flags, bluntly:** (i) FT-off and FT-on differ in MPI transport and the arm order is fixed, so "FT cost" is confounded with the launcher and with drift. (ii) Pinned merged tactics alone can move results by about 5% across these layouts. (iii) Kill and cost runs use different code (overlay), different CUDA graph sets and possibly different A2A kernels. (iv) n=2 with no CI. (v) "Standard" YAML comments cite perf-sanity for values that perf-sanity does not run (stream_interval).
